# deck.gl real-sample dot map, strict fetch-gating, and a Google-Destinations-style destination bar for VayuLok Live (v1)

This branch rebuilds the VayuLok live right-map against the FINAL AGREED DESIGN. The raster Air Quality heatmap (`ImageMapType` → `/heatmapTiles/`) is replaced by a deck.gl `ScatterplotLayer` of REAL `currentConditions:lookup` samples drawn over the Google roadmap through `GoogleMapsOverlay`; all environmental fetching is re-gated so it fires only on an AQI/PM2.5 pill click (not on type/select); the AQI/PM2.5 pills, search focus ring, lime tokens and panel radius are restyled; the photo gallery/number pill move off the map into a photo-led left card; and a new Google-Destinations-style bottom selected-place bar with a feature-detected SearchDestinations/Places hybrid is added, with no "Use my location" control. The chosen architecture is client-side sampling (Option B) over a backend fan-out, for the credential/static-export reasons documented in the RESEARCH doc.

**Watch for:** the left-card AQI/PM2.5 result and the `coreError` retry both hinge solely on the grid's **center cell** parsing — if that one cell fails while other cells succeed, dots render but the card shows no reading and no error (possible); the SearchDestinations building-outline/entrances branch is unverifiable in sandbox and only exercised on a live `*.wecare.digital` origin (confirmed, accepted); the destination bar renders the default "Dawki" place before any user search whenever a key is present (confirmed, matches the mockup).

**Verdict**: APPROVED

## High-level view

The raster-to-vector swap is complete and clean: `ImageMapType`, `HEATMAP_OPACITY`, and every `/heatmapTiles/` reference are gone, and the dots are drawn from real parsed samples through a dynamically-imported `GoogleMapsOverlay`, so the no-key path never loads deck.gl at all. Dot fill comes from the VayuLok no-red ramp converted to RGBA, never Google's `UAQI_RED_GREEN`.

Fetch-gating is the heart of the change and it is implemented as a single layer-activation effect that replaced three place-triggered effects. Selecting or typing a place now fetches nothing; the grid (responsive 3×3/5×5, hard-capped at 25, ≤4 concurrent, abortable, cached by area+grid+layer+10-min bucket) and the single-point left-card reading both fire only when a pill is active, and the center cell is reused as the left-card sample so there is no double-fetch.

The pill/focus restyle lands as specified: inactive pills are transparent with a dark-green outline and text (frosted white fill and backdrop blur removed), the active pill is translucent lime `rgba(209,244,112,.55)` with `#1a3a2a`, the search focus ring is dark-green instead of translucent lime, `--lime-solid #f5fde0` is deleted and photo surfaces now use exact `--lime #d1f470`, and the stage radius is 14px with no resting shadow.

The destination bar is a real keyboard-focusable button inset from the bottom corners so the Google logo and `.gm-style-cc` legal stay clear; it recenters on click and never fetches environmental data. Its hybrid resolve feature-detects SearchDestinations via `importLibrary('search')` and silently degrades to marker + name when the capability is absent — which is the only path that runs in sandbox. Geocoding uses `importLibrary('geocoding')` (not the legacy namespace) and that is covered by a test that deliberately leaves `google.maps.Geocoder` unseeded.

Honest degradation holds end-to-end (no key → no map, no deck.gl import, no bar, zero fetches, left card still renders name/address), no CSS targets the mandated attribution surfaces, the rotating-word hero page is untouched, and the tests are behavioral rather than snapshot-brittle — they drive real state toggles and assert on recorded API calls and the real `getFillColor` output.

### Raster heatmap → deck.gl ScatterplotLayer

The old overlay effect built a `google.maps.ImageMapType` whose `getTileUrl` hit `/v1/mapTypes/${mapType}/heatmapTiles/...` with `UAQI_RED_GREEN`/`PM25_INDIGO_PERSIAN`. That is entirely gone (grep for `ImageMapType`, `heatmapTiles`, `HEATMAP_OPACITY` returns nothing), and the test suite asserts the absence directly: `rec.imageMapTypeOpts` stays empty, `overlayMapTypes` is never pushed, and no fetch URL ever contains `heatmapTiles`, across both AQI and the AQI→PM2.5 switch.

Dots are drawn by a `ScatterplotLayer` pushed onto a `GoogleMapsOverlay`, both imported with `await Promise.all([import('@deck.gl/google-maps'), import('@deck.gl/layers')])` inside the activation effect. Because the import lives behind the key/layer guard, the SSR bundle and the no-key path never pull deck.gl in — the honest-degradation test confirms `deckRec.overlayInstances === 0` with no key. `getFillColor` maps each point's severity band to `DOT_FILL_RGBA` (good `[26,58,42]` → mod `[209,244,112]` → worst `[201,138,46]`), with a dark-green `DOT_LINE_RGBA` outline. The no-red guarantee is tested against the *real* resolver: for every parsed dot the test asserts `fill` is a member of the ramp and never red-dominant (`r>200 && g<80 && b<80` is false).

### Strict fetch-gating on pill activation

Three place-keyed effects — core air+weather+pollen on `[place, refreshNonce]`, forecast/history on `[place]`, and air-history on `[place, historyRange]` — collapse into one effect keyed on `[layer, place, refreshNonce, mapReady]`. When `layer` is null it detaches the overlay and clears `air`; otherwise it builds the grid, fans it out, and renders. The grid is responsive (`window.innerWidth < 640 ? 3 : 5`), hard-capped (`cells.slice(0,25)`), throttled to four workers, abortable via a ref'd `AbortController`, and cached by `${lat.toFixed(3)},${lng.toFixed(3)}|${gridSize}|${layer}|${timeBucket}` with a localStorage mirror. The center cell's richer parse (`airStateFromApiData`) feeds `setAir` so the left-card reading reuses the grid center with no extra request.

```
pill click → layer set → grid fetch (≤4 concurrent, ≤25 cells, abortable)
                              │
          center cell ───────┴──────── other cells
          │                            │
     setAir (left card)          AirDot[] → ScatterplotLayer → overlay.setMap(map)

type / select place → (no environmental fetch at all)
```

The gating is enforced by several independent tests: zero air/weather/pollen/forecast/history/solar on load and on select; on an AQI click the overlay attaches and `currentConditions` fires; everything hitting `googleapis.com` after a click is `currentConditions` only; deactivation clears the overlay (`setMap(null)` or empty layers). These would all fail if the old auto-fetch-on-place behavior returned.

One behavioral asymmetry worth surfacing: the left-card result block (`liveActive && layer && air`) and the `coreError` affordance both depend on the **center cell**. `center` is set only when `i === centerIdx` parses, and `coreError` is `dots.length === 0 && center === null`. If the center cell fails to parse but peripheral cells succeed, the map shows dots while the card shows neither a reading nor the "temporarily unavailable" retry — a silent gap. A first-successful-point fallback for `setAir`, and treating a null center as an error independent of dot count, would close it.

### Pill, focus-ring, lime and radius restyle

The CSS matches the spec and is asserted against the actual injected `<style>` text rather than pixels. Resting `.vl-live-layer` is `background:transparent;border:1.5px solid #1a3a2a;color:#1a3a2a` with the old `rgba(255,255,255,.58)` fill, `backdrop-filter`, and resting shadow all removed; `[aria-pressed="true"]` is `rgba(209,244,112,.55)` with `#1a3a2a` text/border. The search field focus ring flips from `rgba(209,244,112,.78)` to `outline:3px solid #1a3a2a` while keeping the single outer `2px solid #1a3a2a` border. `--lime-solid #f5fde0` is deleted from the token set and the photo page/cell/number-pill backgrounds now use `var(--lime)` (#d1f470); the lone remaining `#f5fde0` is the `poi.park` map tint, correctly left alone. The stage radius is 14px with `box-shadow:none`, and the controls move to `top:84px;right:18px`. The pill test also toggles `aria-pressed` on click so the restyle is proven to be driven by real state, not just a static rule.

### Removed-from-map UI

`mapExpanded`, `.is-expanded`, the Expand/Collapse button, the floating `.vl-live-map-photos` gallery, and the on-map place overlay are all removed (grep clean; dedicated tests assert the Expand/Collapse buttons and `.vl-live-map-expand`/`.is-expanded` hooks are absent and that `.vl-live-map-photos` is gone). The photo rail, tabs and number-only pill now live in the left card's `.vl-live-place-card`, and a test confirms the pill renders inside `.vl-live-left`, never in `.vl-live-right`, with number-only text (`/^\d+$/`, never "{n} photos"). `disableDefaultUI`, `fullscreenControl:false`, `mapTypeControl:false`, `streetViewControl:false`, `keyboardShortcuts:false` are all asserted, with `gestureHandling:'greedy'` retained for drag-pan.

### Left-card honest metadata

`metaFromGooglePlace` extracts primaryType/types/rating/userRatingCount/websiteURI/openNow/summary only when genuinely present (finite numbers, non-empty strings, real booleans), and the extra fields are requested only on the existing keyed select and map-click paths. The card renders facts/attributes/description/supporting-info blocks each behind a presence guard. Two tests pin both directions: a fully-populated place surfaces "Historical Landmark", `4.6`, `1,234`, "Open now", "Official website listed", humanized secondary types and the editorial summary; a bare place renders none of `.vl-live-place-facts`/`.vl-live-place-attrs`/`.vl-live-place-desc`. The PM2.5 result derives its "Current status" word from the existing severity band (`statusWord`), not a new scale, keeping the dot, category and status consistent.

### Destination bar and SearchDestinations/Places hybrid (FEAT-004)

The bar is an inline `<button className="vl-live-map-destbar">` gated on `liveActive && previewPlace.name`, showing the uppercase name, a middle-dot, `primaryType || addr`, and a `›` chevron, with `aria-label` reading "`<name>, <loc/type>`". Clicking it recenters (`setCenter` + `setZoom(16)` + `marker.setPosition`) and fetches nothing. CSS insets it (`bottom:36px`, `max-width:min(420px,calc(100% - 96px))`, centered) so the bottom-corner logo and `.gm-style-cc` legal stay clear, and no rule targets the attribution selectors.

The hybrid-resolve effect (keyed `[place, mapReady]`) first clears any prior polygon/entrance markers and aborts any in-flight lookup, then skips area-like places (no `primaryType`, or a `primaryType` matching `locality|administrative|political|country|region|state|province|postal|neighbo(u)rhood`) per Google's "localities/administrative areas are not valid destination searches" rule. For navigable destinations it feature-detects `importLibrary('search')` + a `searchDestinations` capability; present → it resolves and draws `displayPolygon` as a `google.maps.Polygon` (stroke `#1a3a2a`, fill `#d1f470` @ 0.18, no red) plus entrances as lime circle markers; absent → it degrades silently with marker + bar name and no fabricated geometry. The sandbox stub has no `search` library, so the degraded path is what runs, and a test spies on `Polygon` to confirm **nothing** is drawn there. Tests also confirm: bar carries the resolved name + address segment; select-then-click fires zero environmental fetches and no overlay attach; `navigator.geolocation.getCurrentPosition`/`watchPosition` are never called and no "use my location" control exists; and with no key the bar does not render. The outline/entrances branch itself cannot be exercised in sandbox and is only verifiable on a live origin — accepted, but it has no runtime coverage.

### Geocoding via importLibrary

`Geocoder` is now obtained through `importLibrary('geocoding')` on both map init and the search fallback (`ensureGeocoder`), falling back to the legacy namespace only for an older loader. The regression guard renders with `seedNamespaceGeocoder:false`, asserts `google.maps.Geocoder` is undefined, and proves the component still obtains a working Geocoder — i.e. it must have imported `geocoding`. A separate test confirms a `REQUEST_DENIED` status surfaces the existing "unavailable" error with a Retry affordance rather than being swallowed, while `ZERO_RESULTS` stays benign.

### Dependency, verification, and scope

`@deck.gl/core`, `@deck.gl/google-maps`, `@deck.gl/layers` are pinned at `^9.4.0` (with `@luma.gl/core` deduped transitively). `npm run typecheck` passes; `npm run lint` reports 0 errors (the 8 warnings on this file — `<img>` usage and the line-873 set-state-in-effect — predate this branch); `npx vitest run src/test/VayuLokLive.test.tsx` is 32/32 and the full suite is 929 passed / 3 skipped / 0 failed. `src/pages/vayulok/index.tsx` (the rotating-word hero) is absent from the diff, as required. The retired weather/pollen/forecast/history loaders and their render sections remain in the file in a dormant state rather than being deleted; this keeps the diff reviewable but leaves dead paths behind — worth a conscious decision on whether to prune them in a follow-up.
