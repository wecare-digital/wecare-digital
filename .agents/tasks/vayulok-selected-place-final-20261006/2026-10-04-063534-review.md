# Null selected-place, hard India gate, no-red marker, and final design pass for VayuLok Live (v1)

The selected place now starts `null` instead of defaulting to Dawki: the map opens on a neutral country-level India camera with no card, marker, destination bar, or environmental fetch until the visitor makes a real selection (search-select or a validated map click). A hard India country gate (`isIndiaResult`) is applied to the reverse-geocode, geocoding-search, and autocomplete paths, inspecting the result's country address component and accepting only short code `IN`. The default red Google pin is replaced by a lazily-created `google.maps.Marker` carrying an inline SVG data-URI icon in dark-green/lime/white. The open/closed line is omitted (the modern Place exposes open-now only via the async `Place.isOpen()`, not a static field). The remaining fixes are a photo-fallback correction, a left-card hero photo + notch, and a pill/token/map-border normalization. Scope is clean: only `src/components/VayuLokLive.tsx` and `src/test/VayuLokLive.test.tsx` changed (plus planning notes); the hero and other page sections are untouched, no API key is committed, and no attribution-hiding CSS was added.

Watch for: a stale `outside-india` status message can persist in the search dropdown after a subsequent successful map-click selection — the reverse-geocode success branch never resets `searchStatus` to `idle` (confirmed). Everything else holds up.

**Verdict**: APPROVED

## High-level view

The Dawki default is genuinely gone. `DEFAULT_PLACE` was deleted and replaced by `INITIAL_CAMERA` (a map framing value, explicitly not a selection); `place` state is `null` on load and every selection-driven surface — card, marker, destination bar, AQ grid fetch, solar, geometry resolution — is gated on a non-null selection. Clicking a layer pill with nothing selected fetches nothing.

The India gate is a short-code equality check (`'IN'`) that handles both the classic (`short_name`) and modern (`shortText`) component shapes, rejects results with no country component, and is wired into all three resolution paths. The map-click path iterates rows and takes the first `IN`, keeping the previous selection and surfacing an honest "outside India" status when none pass. The autocomplete path only enforces when the resolved Place actually carries address components, otherwise trusting the India bias — acceptable because that branch is live only on `*.wecare.digital`.

The selected marker is a classic `Marker` with an inline-SVG data-URI icon (dark-green body, lime inner dot, white ring), created lazily on first selection and sized larger than the AQ sample dots. The open/closed line is omitted rather than fabricated from an unreliable field.

The photo-fallback fix now counts any exact photo with a URL as usable (attribution rides along), so an attributed exact photo no longer triggers a needless nearby fetch. PM2.5 severity is driven by real concentration via `pm25Severity`, independent of AQI. Pills, tokens, map-border, and shadows match the spec, and the behavioral test matrix drives real state and handlers rather than asserting constants.

The one real defect is a status-reset gap on the map-click path (see Issues).

### Dawki default removed; neutral camera is not a selection

`DEFAULT_PLACE` (name 'Dawki', lat/lng in Meghalaya) is deleted and replaced by `INITIAL_CAMERA` (22.9734, 78.6569, zoom 5), used only as the `maps.Map` center/zoom at init. `place` state is now `PlaceState | null` starting at `null`. The marker is no longer constructed at map init — only `markerCtorRef` is captured, and the recenter effect builds the pin on first real selection. Every downstream surface short-circuits on `!place`: the AQ-grid effect (`if ( !place ) return;` before building the grid, confirmed ~1031), `loadSolar` (`|| !place`), the geometry-resolution effect, and the render tree, where the whole selected-place block is wrapped in `{ previewPlace && ( ... ) }` and the destination bar in `{ liveActive && previewPlace && ( ... ) }`. Matrix A and A2 confirm this behaviorally: on load there is no `.vl-live-place-card`, no `Dawki` text, no destbar, `markerOpts` is empty, zero `currentConditions` fetches fire, no deck.gl overlay is attached, and the recorded map center sits inside the India bounds at zoom ≤ 6; clicking the AQI pill with no selection still fires zero fetches and attaches no overlay. Both would fail on a revert to the Dawki default. (confirmed)

### Hard India country gate on all three resolution paths

`isIndiaResult` finds the component whose `types` include `'country'` and accepts only when its uppercased short code equals `'IN'`, reading `short_name` (classic Geocoder) or `shortText` (modern Place), and rejecting a result with no country component. On the map-click reverse-geocode it iterates rows with `rows.find( r => isIndiaResult( r ) )`, selects the first `IN`, and on no match sets `searchStatus('outside-india')` and returns without changing the selection — never inventing a foreign location (confirmed ~820–845). The geocoding-search fallback filters rows through `isIndiaResult` and additionally drops rows without a real `geometry.location`, removing the old `DEFAULT_PLACE.lat/lng` coordinate fabrication (confirmed ~1551). The autocomplete `toPlace` path requests `addressComponents` and, when the resolved Place carries a country component, rejects a non-`IN` result; when no country component is present it trusts the `includedRegionCodes:['in']` bias and proceeds — defensible because this branch is only exercisable on a live `*.wecare.digital` origin. Matrix D (accepts the IN stub row), E (rejects a leading BD row and accepts the following IN row — the Dawki-border case named in the constraint), and E2 (a BD-only result selects nothing, draws no marker, and surfaces the outside-India status) all drive the real recorded map-click handler. (confirmed)

The gap: the reverse-geocode *success* branch sets the selection but does not reset `searchStatus`, so a stale `outside-india` message from a prior foreign click lingers in the dropdown. The search-select path resets to `idle`; the map-click success path should too. (confirmed — see Issues #1)

### No-red brand marker, lazily created, distinct from AQ dots

`BRAND_MARKER_SVG` is a 36×48 teardrop with a `#1a3a2a` body (`#ffffff` stroke) and a `#d1f470` inner circle, encoded as a `data:image/svg+xml` URI so no asset fetch is required. The recenter effect creates the `Marker` only on first selection and no-ops entirely while `place` is null. The 36×48 pin is deliberately larger than the 9px-radius ScatterplotLayer dots, so the selection reads distinctly from a data point. Matrix K reads the recorded marker opts, asserts the icon URL is a `data:image/svg+xml`, that the decoded SVG contains `#1a3a2a` and `#d1f470`, and that it matches none of `#ff0000|#f00|red`. On the honest-degradation path the recenter effect's guards (`!map`, `!w.google?.maps`, `!place`) all hold and no marker is ever built. (confirmed)

### Photo-fallback fix

The enrichment effect previously treated only attribution-free exact photos as usable (`attributions.length === 0`), which wrongly discarded an attributed exact photo and kicked off a `searchNearby` fetch. It now uses `( target.photos || [] ).some( photo => Boolean( photo.url ) )`: any exact photo with a URL counts, attribution rides with it in the figcaption, and `searchNearby` runs only when there is genuinely no usable exact photo. Matrix L confirms the author-attribution figcaption and its contributor link survive into the left card. (confirmed)

### Open/closed omitted, not fabricated

`openNow` is removed from `PlaceState`, `GooglePlaceLike`, and `metaFromGooglePlace`; `regularOpeningHours` is dropped from `PLACE_META_FIELDS`; and the "Open now/Closed now" attribute line is gone — open-now is the async `Place.isOpen()`, not a reliably populated static field, so rendering it statically would be fabricating a datum the API does not deliver. The metadata test now asserts `regularOpeningHours` is not among the requested fields and that neither "Open now" nor "Closed now" appears. (confirmed)

### Pills, tokens, map border, shadows

The active pill fill moves to the spec target `rgba(209,244,112,.6)` with `#1a3a2a` text and border; the inactive pill is `background:transparent` with no `backdrop-filter` and no resting shadow; the focus ring stays `outline:3px solid var(--green)` offset 3px. The map stage border is normalized from the lime `rgba(209,244,112,.92)` to the homepage hairline `1px solid #e5e7eb` with `box-shadow:none`, so lime is reserved for punctuation/active rather than a resting panel frame. The floating destination bar keeps a light elevation (reduced to `0 1px 4px rgba(26,58,42,.08)`, hover `0 4px 12px rgba(26,58,42,.12)`) because it sits over the map. Matrix J reads these rules out of the rendered styled-jsx and asserts the exact `.6` value (not opaque `var(--lime)`), transparent resting background with no backdrop blur, the dark-green focus ring, the `#e5e7eb` stage border with no lime and `box-shadow:none`, and the absence of any expand/collapse control. (confirmed)

### Left-card hero photo + notch

The left card leads with one large `.vl-live-photo-hero` (232px, `object-fit:cover`) carrying its own author-attribution figcaption; additional photos stay in the existing horizontal rail and nothing floats on the map. The card is wrapped in an outer `.vl-live-place-cardwrap` (`overflow:visible`, `tabIndex={-1}`, focus-visible ring) so the centred `.vl-live-place-notch` can escape the inner card's clipped rounded corner; all markup stays inline in the return so styled-jsx keeps the `vl-live-` scope on the notch. The destination-bar click now scrolls and focuses this card via `placeCardRef`, guarded by a `typeof scrollIntoView === 'function'` check for jsdom. Matrix F stubs `Element.prototype.scrollIntoView` and asserts the scroll call plus that `document.activeElement` lands on the card; Matrix L asserts the hero image is present, the count pill shows an integer with aria-label `N place photos`, and the referee SVG path is byte-identical. (confirmed)

### PM2.5 driven by real concentration

The ScatterplotLayer `getFillColor` picks `pm25Severity( d.pm25 )` when the active layer is `PM25` and `d.pm25` is finite, otherwise `aqiCategory( d.aqi ).sev` — PM2.5 severity comes from the real `pm25` concentration band, independent of AQI (confirmed ~1165). The color ramp (`#1a3a2a` → `#3da35a` → `#d1f470` → `#e8c547` → `#c98a2e`) contains no red, and severity is also carried by numeric value and category word, not color alone. Matrix N proves the behavior: AQI 320 (worst AQI band) with pm25 20 (cleanest pm25 band) must color every dot the good fill, not the worst fill, and the left PM2.5 result must print `20`, not `320`. This test would fail if severity reverted to AQI-derived. (confirmed)

### Attribution, degradation, and scope

The key is read only from `process.env.NEXT_PUBLIC_GOOGLE_MAPS_KEY`; no literal key is committed. No CSS targets `.gm-style-cc`, `a[href*="google"]`, or `img[alt="Google"]`, and the destination bar and deck.gl overlay stay inset from the map corners. With no key, `liveActive` is false, no script loads, no deck.gl import runs, and no card/marker/destbar/fetch appears — the non-map shell still renders. The diff touches only the two in-scope files plus `.agents/tasks` planning notes; `src/pages/index.tsx` and the VayuLok hero are untouched. Gate results: `npm run typecheck` clean, `eslint` on both files reports 0 errors (9 pre-existing-style warnings — `set-state-in-effect` and `no-img-element`, the latter including the new hero `<img>`, matching the file's established pattern), and `vitest run src/test/VayuLokLive.test.tsx` passes 44/44. (confirmed)

### Test matrix is behavioral, not static

The matrix tests drive the real search→select flow via a `selectMumbai` helper (fires the combobox change, mouses down the option, waits for the resolved name in the left card) and the recorded map-click handler, then assert on rendered DOM, recorded constructor opts, and the live `getFillColor` function. No matrix test asserts a bare constant or mocks away the logic it claims to cover: K reads the actual icon the component passed, N calls the component's own `getFillColor` with real data, E/E2 exercise the real `isIndiaResult` gate through scripted rows, and J reads the component's rendered styled-jsx rather than a hardcoded string. Each would fail on a revert of the behavior it targets. (confirmed)
