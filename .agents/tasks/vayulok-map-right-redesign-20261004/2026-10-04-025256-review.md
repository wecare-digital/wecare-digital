# VayuLok map: number-only photo pill, place-card removal, and right-side map redesign (v1)

The change reworks the right-hand map panel of `src/components/VayuLokLive.tsx`. The numeric photo pill is reduced to a bare count plus the owner's referee SVG on a lime background; the overlaid place card (name/metrics/insight/View-details) is deleted wholesale and the surviving photo rail is lifted into a standalone top-right overlay; the map surface becomes a single 20px-rounded panel with a horizontally-centred search field and a new keyboard-operable expand/collapse control that grows the stage from 340px to 560px. The autocomplete data path (Google Maps India SKU via `AutocompleteSuggestion.fetchAutocompleteSuggestions` with a per-session token, India-scoped) is untouched by design. Everything else in the diff is task-state JSON metadata.

**Watch for:** nothing blocking. The place-card removal also deleted the per-candidate preview weather/air fetch block (`setMapCandidateWeather`/`setMapCandidateAir` and their two `fetch` calls) — confirmed intentional, since the card that consumed that data is gone, and it removes a network call rather than adding one (confirmed). A removed `istClock` interval and its `istTimeLabel` helper are also gone with the card; no remaining reference (confirmed).

**Verdict**: APPROVED

## High-level view

Requirement 01 is met literally: `.vl-live-photo-count` now renders the referee SVG — exact `height="24px"`, `viewBox="0 -960 960 960"`, `width="24px"`, `fill="#1f1f1f"`, exact path `d`, `aria-hidden="true"` — followed by `<span>{count}</span>` with no "photos" word, on a `var(--lime)` pill, and the photo cells sit on `var(--lime-solid)`. Requirement 02 is met: the `.vl-live-map-preview` card and all its sub-markup and styled-jsx are deleted, and no replacement left-side card is introduced. The photo rail now lives in a new `.vl-live-map-photos` overlay inside the map stage, so the pill survives the card's removal. A dedicated test asserts the card, its CTA, and the "photos" label are all absent.

Requirement 03 is met across its parts: the stage radius moves 14px→20px with canvas/fallback inheriting it; the search field is centred (`left:50%` + `translateX(-50%)`) with top spacing and keeps its 2px `#1a3a2a` outer border plus a lime focus ring, neutralised against global input boxes with `!important`; selection via search or map-click drives the existing recenter effect, and the new `.vl-live-map-expand` button toggles `is-expanded` with `aria-expanded` while `keyboardShortcuts:false` and `gestureHandling:'greedy'` are preserved.

The hard constraints survive: no CSS targets `.gm-style-cc`, `a[href*="google"]`, or `img[alt="Google"]`; overlays stay top-anchored and inset so Google's bottom-corner logo stays visible even in expanded mode; all styled markup remains inline in the return tree; the key is still read only from `process.env.NEXT_PUBLIC_GOOGLE_MAPS_KEY`; and the honest-degradation test (no key → no map, no canvas, zero fetches) is unchanged and green.

### Number-only pill and the referee SVG (req 01)

The pill markup is now the referee SVG followed by `<span>{ displayPhotos.length }</span>` — the former `{n} photos` text node is gone. The SVG attributes match the instruction byte-for-byte (`height="24px"`, `viewBox="0 -960 960 960"`, `width="24px"`, `fill="#1f1f1f"`, and the exact path), and it carries `aria-hidden="true"` so screen readers fall through to the pill's `aria-label={ \`${displayPhotos.length} place photos\` }`. The pill background is `var(--lime)` and `.vl-live-photo-page` / `.vl-live-place-photo` both move to `var(--lime-solid)`, so a loading or absent image reads as the lime behind the pill rather than the old grey `#eef3ef`.

### Place-card removal and the standalone photo overlay (req 02)

`.vl-live-map-preview` is removed from both the return tree and the styled-jsx, including the head (`vl-live-card-h`/`vl-live-map-address`), the preview metrics grid, the insight block, the preview heatmap scale, and the `vl-live-view-details` CTA. No left-side replacement card is built — the instruction defers that to a later task. The photo rail is relocated into a new `.vl-live-map-photos` overlay guarded by `displayPhotos.length > 0`, inside `.vl-live-map-stage`.

Removing the card also removed its data feeders: the two `setMapCandidate*` state slots, their reset in the place-change effect, the `previewWeather`/`previewAir` derivations, and the map-click handler's `Promise.all` weather+air preview fetch — that data existed only to populate the deleted card, so this removes a network call rather than adding one. The map-click handler now calls `setPlace(next)` alongside `setMapCandidate(next)`, which routes a clicked location into the real recenter + live-data path (req 03C).

### One rounded panel, centred search, expand control (req 03)

The stage radius goes to 20px with `border-radius:inherit` on the canvas and fallback, so the panel reads as a single rounded surface. The search overlay is centred with `top:18px;left:50%;transform:translateX(-50%)` at all three breakpoints (the tablet and phone media queries were updated to keep the centring instead of the old left-pinned position). The field keeps a 2px `#1a3a2a` border with a lime `rgba(209,244,112,.78)` focus ring on `:focus-within`; the inner `<input>` is zeroed with `background/border/outline/box-shadow/border-radius/padding` `!important` resets (including a `:focus,:focus-visible` reset) so global `inner-pages.css`/`Dashboard.css` input-focus boxes can't reintroduce an inner frame. The owner-approved border colour is `#1a3a2a`, not lime — matched.

The expand control is a real `<button type="button">` with `aria-expanded={ mapExpanded }` and a label that flips between "Expand map"/"Collapse map", toggling `.vl-live-map-stage.is-expanded` (340px→560px, with a height transition that is disabled under `prefers-reduced-motion`). It is kept inline in the return so styled-jsx keeps its scope. `keyboardShortcuts:false` and `gestureHandling:'greedy'` and `restriction:{INDIA_BOUNDS,strictBounds:true}` are all preserved, so Google's arrow-pan can't fight India strict bounds while drag-pan and the explicit button provide interaction — the test asserts both map-option values and the full keyboard-operable toggle cycle.

The autocomplete path is confirmed unchanged: `AutocompleteSuggestion.fetchAutocompleteSuggestions` with a lazily-created `AutocompleteSessionToken`, `includedRegionCodes:['in']`, `region:'in'`, `locationRestriction:INDIA_BOUNDS`, geocoding only as fallback.

### Palette and attribution constraints (req 04 + hard constraints)

No red is introduced anywhere in the added CSS — the only new colour literal is the referee SVG's `#1f1f1f`, which the instruction mandates. The removed CTA's `prefers-reduced-motion` entries were cleaned up and a `.vl-live-map-stage{transition:none}` entry added for the new height animation. No CSS in the file targets `.gm-style-cc`, `a[href*="google"]`, or `img[alt="Google"]` (only descriptive comments mention them). All overlays — search, layer controls, and the photo overlay — are top-anchored with left/right insets and never pinned to the bottom, so Google's bottom-corner logo and legal text stay visible, and the expanded stage only grows downward from a top-anchored overlay, so the inset is preserved in expanded mode.

### Test coverage

Two tests were added: one asserts the expand control is an accessible keyboard-operable button that toggles `is-expanded` and `aria-expanded` through a full cycle and re-confirms `keyboardShortcuts:false`/`gestureHandling:'greedy'`; the other asserts the removed card, its CTA, and the "photos" label are gone. The pre-existing honest-degradation test (no key → no script, no `.vl-live-map-canvas`, zero fetches) is untouched and still passes. The full suite runs 13 green.

Not tested: the exact referee-SVG attributes (viewBox/path) are not asserted, so a future edit could silently alter the icon without a failing test; and there is no assertion that the pill renders the bare number without the word (the "photos"-absent test covers the removal but not the number presence). Neither gap is blocking given the literal match in the current diff.
