## Suggested unification scope

Use a shared **public** notification presentation component for transient action feedback, with the same lime/forest visual language, semantic type (success/error/warning/info), accessible `role`, and consistent dismiss behavior. Keep input-validation errors, payment uncertainty, data-load failures with retry, and other persistent notices **inline until resolved**. Preserve the existing rule: a Meta template acknowledged by the API is `accepted`, not `delivered`; never auto-retry an ambiguous send. A design-system change should not turn real error messages into four-second disappearing toasts.
