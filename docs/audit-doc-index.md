# Audit & inventory doc index

One place to tell which audit/inventory/consolidation docs are **current**, which
are **superseded** (and by what), and which are **point-in-time evidence** (dated,
kept as a record, not maintained). Built 2026-10-16 as part of the deep audit
(`docs/execution/deep-audit-20261016.md` §7) and refreshed on 2026-10-28 after
the platform-wide 360° review.

Rule of thumb: **do not delete point-in-time evidence** — a dated audit is a
record of what was true then, and the project's own guidance is that an honest
"this was measured on date X" beats a deleted file or a stub. Superseded
*living* docs can be trimmed to a pointer once their replacement is stable.

## Dead-code sweep note (scripts/)

A grep-for-references pass over the 191 `scripts/*.py` flagged a handful with no
in-repo reference (e.g. `amplify_trigger_build.py`, `backup_blog_posts.py`,
`clean_shell_history.py`, `post_deploy_health.py`, `scrub_kiro_permissions.py`).
**These were NOT removed.** "No in-repo reference" is a weak signal: most are
standalone operational tools meant to be run by hand, which is legitimate. Deleting
them on a grep result alone risks removing a working ops tool. If a scripts cleanup
is wanted, it should be a deliberate, per-script owner decision — not an automated
delete — consistent with the steering rule to delete *dead* code, not merely
*unreferenced* code.
