# Phase 1 - Dev Toolchain Security Bump (2026-11-02)

Scope: the ROOT npm install root only (dev toolchain). The separate `amplify/`
install root and its lockfile were not touched. Goal was to reduce the moderate
dev-chain npm audit advisories without weakening the minimatch/braces security
mitigations.

## Applied upgrades

- `eslint` `^9.39.5` -> `^10.14.0` (major). ESLint 10 engines allow `^22.13`, so
  it installs and runs on the Node 22 host (the EBADENGINE warning for the
  project's own `>=24` engine is non-fatal).
- `eslint-config-next` `^16.4.3` -> `^16.4.4` (patch).
- `next` `^16.4.3` -> `^16.4.4` (patch). Moved in lockstep with
  `eslint-config-next`.
- `eslint-plugin-react-hooks` bumped to `7.1.1` transitively via
  `eslint-config-next@16.4.4`.

`typescript-eslint` stays at `8.72.1` (resolved transitively via
`eslint-config-next`; `8.72.1` is the latest release, no newer major exists).
No explicit `typescript-eslint` devDependency was added.

`package-lock.json` was regenerated by `npm install` and committed.
`eslint.config.mjs` required no changes: ESLint 10 + react-hooks 7 run with 0
errors and no renamed/split rule affected the existing config.

## Deferred upgrades

- `typescript` `6.0.3` -> `7.0.2` DEFERRED. `@typescript-eslint/typescript-estree@8.72.1`
  declares peer `typescript >=4.8.4 <6.1.0`. TypeScript 7.0.2 falls outside that
  peer range, so bumping TS to 7 would break the typescript-eslint chain used by
  `eslint-config-next`. No typescript-eslint release supports TS 7 yet, and
  `8.72.1` is already the latest major. TypeScript stays at `6.0.3` (inside the
  peer range).

## npm audit (root install root)

| Severity | Before | After |
| -------- | -----: | ----: |
| critical | 0      | 0     |
| high     | 0      | 0     |
| moderate | 15     | 5     |
| low      | 0      | 0     |
| info     | 0      | 0     |
| total    | 15     | 5     |

Residual advisory packages (after): `eslint-config-next`, `eslint-plugin-import`,
`eslint-plugin-jsx-a11y`, `eslint-plugin-react`, `minimatch`.

The residual advisories trace to legacy `minimatch@3.1.5` copies nested under
`eslint-config-next`'s `eslint-plugin-import`, `eslint-plugin-jsx-a11y`, and
`eslint-plugin-react`. That legacy `minimatch` is intentionally NOT overridden
(major < 9 band) and is verified safe by the preprocessing guard (its source
lacks `firstPhasePreProcess`/`optimizationLevel`). The ESLint 9->10 bump moved
ESLint's own direct `minimatch` into the `minimatch@>=9 -> 11.0.4` override
band, which cleared 10 of the 15 advisories.

**npm audit is NOT declared clean.** The 5 residual moderate advisories are
reported honestly. No `npm audit fix --force` was run and no
suppression/ignore entries were added.

## Preserved mitigations

- The root `package.json` `overrides` block (lodash, fast-xml-parser,
  immutable@3, mysql2, csv-parse, xcode>uuid, glob, minimatch@>=9 -> 11.0.4) is
  unchanged.
- The three guard scripts
  (`scripts/guard_minimatch_preprocess.cjs`, `scripts/check_minimatch_preprocess.cjs`,
  `scripts/guard_braces_depth.cjs`) and their lifecycle hooks
  (postinstall / prebuild / preamplify / preamplify:deploy / precap:build) are
  unchanged. All three guards pass (exit 0) after the bump.
