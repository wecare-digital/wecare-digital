# Secrets consolidation (Workstream B)

Measured 2026-10-14 from metadata only (no secret value read). Per-secret detail:
[`secrets-access-matrix.md`](secrets-access-matrix.md), regenerated by
`scripts/secrets_access_matrix.py`.

## Current state

- **19 active** secrets, **9 scheduled for deletion** (requested 2026-09-20 and 2026-10-07 with
  30-day windows; not billed). No secret has rotation enabled.
- KMS: 15 active secrets use `aws/secretsmanager`; 4 active (`bing/api`, `google/ads`,
  `google/cloud`, `plivo/api`) and 2 scheduled ones use the customer key `9b5b8734…` ($1/month).

## Findings, in priority order

1. **The shared role defeats per-secret isolation.** `wecare-digital-lambda-role`, used by 61
   of 76 functions, allows `secretsmanager:GetSecretValue` on `secret:wecare/*`. Every one of
   those functions can read all 19 secrets, including the Razorpay key, the OTP pepper, the
   backup recovery passphrase, the stored AWS access keys and the exposed GitHub PAT. Grouping
   or splitting secrets changes nothing while this wildcard exists. It also still grants the
   retired `wecare/payu-*`.
2. **The exposed GitHub PAT is still the original token.** One version since 2026-08-26; its
   description says it is a classic near-full-scope token exposed in an agent transcript on
   2026-08-25. Its only source consumer, `wecare-workspace-mcp`, runs under its own role
   (`wecare-workspace-mcp-runtime`); the 61 shared-role functions can read it without needing it.
3. **Four secrets have no Lambda consumer** yet were readable by all 61 functions:
   `aws/iam-access-keys` and `config/webhook-registry` (scripts only),
   `backup/recovery-passphrase` (`scripts/secrets_backup.py` only), and `meta/payments` (named in
   `.env.local.example` as the payment-config mapping). Three of them are now denied to the
   shared role (B-1a).
4. **The operator CLI runs as the account root user** with long-lived root access keys
   (`aws sts get-caller-identity` → `arn:aws:iam::775261844268:root`). Agents, including the one
   that force-deleted secrets, inherit full, unrestrictable access.

## Target architecture

- **One standard, many secrets.** No universal JSON secret. A reader of a JSON secret gets
  every field, so grouping is limited to fields every reader already needs with matching
  rotation. On this inventory no pair meets that bar well enough to beat $0.40/month.
- **Naming.** Existing names stay (a rename means a new secret, a coordinated redeploy of every
  consumer and a month of double billing). New secrets use `wecare/prod/<domain>/<name>` with
  domains `payments`, `communications`, `seo`, `integrations`, `security`.
- **Isolation by role, not by name.** Each function reads only the ARNs it uses. Payment keys,
  the webhook secret, the OTP pepper, the Flow private key, the backup passphrase and the GitHub
  credential stay separate secrets.
- **Access helper.** `lambda_utils/secrets_access.JsonSecretCache` already meets B5: bounded
  TTL (≤300 s), AWSCURRENT/AWSPENDING awareness, rotation-generation invalidation, required-field
  checks, fail-closed errors without values, no fallback; 12 synthetic-fixture tests pass. Only
  the Razorpay modules use it; 36 files call `get_secret_value` directly. Adopt it when a
  function is touched; a fleet-wide refactor is not justified by risk or cost.
- **Parameter Store Standard** only for configuration the owner confirms holds no secret field
  (candidate: `config/webhook-registry`). Never plaintext SSM for a secret.

## Backups (B8)

`wecare-credential-backups-775261844268`: versioning on, SSE-KMS, public access blocked, no
lifecycle rule, one object with 2 versions (2026-09-25, 51,706 B; 2026-09-26, 51,933 B). Both
predate the Wix and Airtel retirements, so they hold those credentials, and they are 18 days
older than today's secret set. Deleting them would also destroy unrelated recovery material.
The safe order is B-5: write a fresh archive, verify it decrypts (`scripts/verify_backup_artifact.py`),
then let the owner expire the old versions. Provider-side revocation of the Wix keys is moot
now that the Wix site is deleted; the Airtel credentials should be revoked at Airtel if the
account still exists.

## Cost

19 × $0.40 = $7.60/month storage, about $0.12–0.25/month in API calls (23,835 calls in
October 1–14), plus $1/month for the customer key. The realistic consolidation saving is up to
3 secrets ($1.20/month, POTENTIAL, after B-3/B-4). The value of this workstream is B-0 to B-2,
not the saving.
