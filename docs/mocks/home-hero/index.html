Section 1 of the home page · below the header

The hero says who you build for. It never asks anyone to do anything.

Seven flaws in the top section of src/pages/index.tsx, each with the smallest fix that resolves it. The typography, colour, rotation timing and easing are not up for discussion here — they are reused byte-for-byte. What changes is what the section contains, what it ships before JavaScript runs, and how much empty page comes first.

The two that actually matter

F1 — the hero is a statement with no door out of it

The section contains exactly three things: an h1, a rotating pill, and one sentence. No button, no link, no input — not one focusable element. A keyboard user tabs logo → chevron → and lands in the section below the hero. A mouse user's only forward path is a 46px chevron in the header or a scroll.

This is a recent regression, not an original choice: the slot above the headline used to hold a lime brand badge. It was removed for good reason (it restated the header lockup 109px below it) and nothing took its place — so the hero lost its only non-text element and never gained an action.

Fix: Start a request → to /contact/ (the real conversion route, already public) and See how it works to the flow section anchor. Geometry straight from button.css — .btn-lg at 52px, 13px radius, .btn-primary lime on a 2px #1a3a2a border. No new colours, no new component.

F2 — the headline is broken in the HTML you actually ship

.home-cycle is display:inline-block and every .home-cyc-word inside it is position:absolute. Its width comes from one place only: the inline width:Npx written by the measurement effect. That effect runs in useEffect, and cycleW starts null.

  • This is a static export. The exported HTML contains a pill of width 0 — the headline reads “Everyday AI, built for ( • )”.
  • On every load there is a painted frame at width 0 before hydration measures, then a 278px jump inside the h1.
  • With JS off, blocked, or failed, the sentence never completes.

The page already knows this is unacceptable — the closing band was deliberately rewritten so its animation is opt-in, with the comment “an entrance effect must never be the reason content cannot be read.” The hero breaks that same rule, in the h1.

Fix: one rule. While unmeasured, the first word is position:relative instead of absolute, so .home-cycle has a correct intrinsic width with no JS at all; the effect then takes over and nothing about the glide changes. Every constant HomePage.test.tsx pins is untouched.

F3 — 188px of nothing, in a slot whose contents were deleted

padding-top:108px clears the fixed header, then .home-layout adds 80px. That 80px was tuned when a badge sat in it. The badge went; the padding stayed. On a 1080p laptop (~900px of visible page) 21% of the fold is white space before a single word, and the sub-line is the last thing above it.

Fix: padding:80px 24px 96px → 48px 24px 96px (mobile 48px → 32px). Bottom padding is untouched, so the 96px section rhythm below the hero does not move. Note: HomePage.test.tsx:258 asserts the literal string padding:80px 24px 96px — that assertion has to move with the value. Turn on the spacing overlay in the bar above to see the band.

F4 — the proposition is time-locked and unpausable

Four words at 2400ms means 9.6 seconds to learn what the company does. Someone who lands, reads for three seconds and leaves has been told you build for consumers and nothing else. And because there is no pause, a visitor who slows down to read the word gets it swapped mid-sentence.

Fix: hold the interval on pointerenter / focusin and resume on leave — four lines, no visual change, nothing retuned. Deliberately not proposed: a static chip row repeating the four audiences. It would restate copy the pill already carries. If the 9.6s still reads as too slow after the CTAs land, the next lever is the interval itself, and that is a decision for all four hero surfaces at once (tools/browser/animcheck.js enforces it).

F5 — an all-text fold, with 40% of the measure empty (frame C)

The h1 is capped at 900px inside a 1300px container and the sub at 560px, so the right side of the fold is blank. The first visual thing on the site is the black terminal panel, 96px or more below. The reference layout this hero is modelled on pairs the headline with a product visual above the fold; here the product is out of sight until you scroll.

Fix, and it needs your call: frame C puts the existing WorkflowTerminal in a 430px right column from 1024px up. No new asset, no new illustration. But it has a consequence for the next section: the same panel currently sits 96px below, so either the hero gets a short static crop and the section below keeps the live 8-step run as the payoff (what C shows), or the panel moves up entirely and .home-flow keeps only its copy column. That second option is the cleaner one — it is also a change to section 2, so it waits for section 2.

The diff, in words

Five files, and only one of them is the home page.

src/pages/index.tsx

  • F3 — .home-layout: padding:80px 24px 96px → 48px 24px 96px; the mobile query 48px 16px 64px → 32px 16px 64px.
  • F2 — add is-unmeasured to .home-layout while cycleW === null, plus one rule: .is-unmeasured .home-cyc-word:first-of-type{position:relative;opacity:1;transform:none}.
  • F1 — a .home-cta block after .home-sub, inside .home-hero. It has to stay inline in the return tree: styled-jsx only scopes JSX it can see statically, which is why BrandBadge arrived unstyled and why a renderLink() helper broke the header.
  • F4 — onPointerEnter/onPointerLeave/onFocus/onBlur on .home-hero holding a paused ref that the interval checks. The prefers-reduced-motion early return stays exactly as it is.

src/test/HomePage.test.tsx

  • Line 258 pins padding:80px 24px 96px — update to the new value.
  • The absence assertion at line 115 checks for .home-eyebrow, .brand-badge. .home-cta is neither, so it still passes — and it should stay, because the CTAs are not a reason to let a second brand lockup back in.
  • Worth adding: an assertion that .home-hero contains at least one focusable element, so F1 cannot silently regress.

src/styles/button.css

  • F7 — add 'Inter' to the head of .btn's font stack. This affects every button on the site, which is the point: they are all currently rendering in the system face.
  • Replace transition:all 0.15s ease with the three properties that actually animate, on cubic-bezier(.16,1,.3,1) from design-tokens.ts. all also transitions box-shadow, which delays the focus ring.

src/lib/design-tokens.ts + src/styles/tokens.css

  • F6 — layout.headerHeight = 60 is the dashboard bar, not the public header. Add publicHeaderHeight: 108 / publicHeaderHeightMobile: 96 and a --wc-hdr-h custom property, then let the four hardcoded copies read from it. Note tokens.css is not currently imported by _app.tsx, so this needs the import added before the variable resolves.

Deliberately not touched

  • The 2400ms interval and every easing — tools/browser/animcheck.js asserts all four hero implementations share them.
  • letter-spacing:-0.04em, and no per-breakpoint override. The em value self-scales; three px values caused a 2.75× optical swing.
  • .home-head-line{display:block}. The pill must keep its own line or the page below shifts every 2400ms.
  • font-weight:600 on the h1, lighter than the 700 section h2. Intentional inversion.
  • The four tint/dot pairs, reused from the Grahak OS and VayuLok rotations. No new colours anywhere in this proposal.
  • The copy. Both strings are unchanged; the only new words are the two button labels.

Open questions for you

  1. Primary CTA target. /contact/ is the only public conversion route and its own description is “Submit, amend or track a request.” If the real primary action is something else, say so — the label and the target both change.
  2. Frame C or frame B. C fills the fold but duplicates a panel that is 96px below. Moving the terminal up entirely is cleaner and is a section-2 change.
  3. The 108px header. It costs 10% of a laptop fold before the hero gets a say. Out of scope here, but it is the largest single number above the headline.
